# Signal Brief

A weekly AI brief that reads the week's AI developments and says what they mean for a non-technical health-tech founder. Fetching and reasoning run automatically 3x/week via GitHub Actions + Claude. The static page reads the generated `digest.json`.

The demo point: the AI **verdict** (BUILD-RELEVANT / WATCH / SKIP) is the hero, not the links. It shows the reasoning layer, running in public.

## What's in here

- `index.html` — the public page (single file, renders `digest.json`, falls back to a sample).
- `digest.json` — the current brief data (regenerated by the Action; a sample ships so the page renders on day one).
- `scripts/build-digest.mjs` — fetches source feeds, asks Claude for a founder-facing verdict, writes `digest.json`.
- `.github/workflows/digest.yml` — runs Mon/Wed/Fri, commits the digest, deploys Pages.

## Setup (about 15 minutes)

1. **Create the repo.** Make a new public GitHub repo and push these files.

2. **Add your API key.** Repo → Settings → Secrets and variables → Actions → New repository secret.
   Name it exactly `ANTHROPIC_API_KEY`, value = your Anthropic key. This stays server-side; it is never in the public page.

3. **Enable Pages.** Repo → Settings → Pages → Build and deployment → Source = **GitHub Actions**.

4. **Set your booking link.** In `index.html`, replace `const CAL_URL = "#";` with your Cal.com/Calendly URL.

5. **First run.** Repo → Actions → "Build weekly brief" → **Run workflow**. This generates a real `digest.json` and deploys. After that it runs on schedule.

Your URL will be `https://<your-username>.github.io/<repo-name>/`. That is the link you put on LinkedIn.

## Verify the feeds on first run

The feed URLs in `scripts/build-digest.mjs` are the commonly-used addresses, but Substack custom domains change. If a source reports "no new post" for weeks, the feed URL is likely wrong, not the source silent. Open the source, find its real `/feed` or RSS link, and update the `SOURCES` array.

## Traffic tracking

A Cloudflare Web Analytics snippet is already in `index.html`, just before `</head>`, with a placeholder token. It is inert until you set a real token.

1. Cloudflare dashboard → Web Analytics → add your Pages URL.
2. Copy the token it gives you.
3. In `index.html`, replace `YOUR_CLOUDFLARE_TOKEN` with it.

No cookie banner is required (Cloudflare Web Analytics is cookieless). Traffic stays near zero until you link the site somewhere, so the first real data point is your launch post, not deploy day.

## Cost

Each run makes one small Claude call per fresh post (five sources, so at most ~5 calls, 3x/week). This is light. Default model is `claude-sonnet-5`; switch to `claude-haiku-4-5-20251001` in `build-digest.mjs` for lower cost.

## Guardrails

- Only real fetched article URLs are ever shown. Claude summarizes supplied text only and is told not to invent links or facts.
- Claude writes the triage. **You still read the originals and form the judgment you sell.** The summaries are a prop, not a replacement for your own reasoning.

## Upgrade path: live per-visitor analysis

This version bakes the analysis at build time (secure, because the key never ships to the browser). If you later want a visitor to paste their own article and get a live verdict, add a serverless function (Vercel/Netlify) that holds the key and calls Claude, and have the page call that function. That is a different deploy; ask when you want it.
